## 独立预设、接口思考与作品资料关联（0.5.0）

小说讨论、正文生成和本地 Agent 分别保存独立预设。小说顶部“预设与思考”、Agent 的“参考设置”可按需展开；支持命名、复制、删除及 JSON 导入 / 导出。默认采用独立的提示词、32768 上下文和 4096 输出上限，聊天补全支持独立温度 / Top P；模型与连接仍使用原生当前选择。可以分别开启原生预设文本继承、原生参数继承、角色卡和世界书参考。参数继承可能重新使用原生较小的输出上限，请查看生成记录中的有效设置。切换模式不再自动切换原生参数预设，避免跨模式污染。

原生预设继承仅提取当前启用的普通文本条目及常用宏，保留条目顺序，跳过 marker 和关闭条目；不完整复刻角色扮演的深度插入及任意插件宏。Agent 的工具和文件权限规则继续保留。导出的独立预设只包含白名单参数和提示词，不包含 API 密钥；原生社区预设应在原生界面导入后选择继承。完整独立参数 / 思考功能针对聊天补全接口；其他原生生成类型保留基本输出长度控制，不承诺同等兼容性。

DeepSeek、OpenAI 及兼容来源使用增量流；Claude、Google 和 Cohere 的原生流格式不同，小说对这些来源使用原生后端转换的非流式正文，提示兼容范围，暂不提供其 Agent 工具适配。思考字段能否保留取决于原生后端转换，未返回时不制造替代内容。这些供应商没有通过真实账户验收。

接口通过 reasoning_content / reasoning 字符串明确返回的思考内容可折叠显示，与正文分开。显示与保存分别选择；默认都关闭，未保存的内容只保留在本次窗口内，正文候选的思考只在候选预览显示。不会自行制造“思维链”，也不把正文中的 think 标签冒充内部思考。不提供思考的模型正常显示正文。社区正则默认不进入新模块的消息渲染、工具参数、文件原文或修改对照；原生世界书自身的激活规则仍可能执行。第三方插件与页面共享运行环境，界面隔离不等于任意插件脚本的安全沙箱。

小说可关联已授权的单个资料文件夹，并显式选择最多 4 份参考文档；每份最多读取前 12000 字符，界面会说明截断。Agent 文档预览可“引用到当前作品”，回复可显式采用到当前章节。项目摘要先保存为草稿，作者确认保存后才能选择作为参考；带来源的摘要会核验文档版本，来源变化时小说阻止发送旧摘要，Agent 忽略旧摘要并提示重新阅读。已读记录按版本和实际范围合并；这不是自动语义索引或自动确认设定。原有文档修改对照、保存前备份、历史恢复和作品快照继续保留。

本地交付位于 dist/0.5.0；免安装版需保留整个 win-unpacked 目录。正式安装目录不会因生成测试版而变化，使用方式见 UPDATE.md。启动日志新增固定的 Node / 原生初始化 / 前端构建 / 监听阶段，并在已识别的原生启动失败时及时报错；偶发冷启动慢仍需真实冷启动证据，不能由连续重启的成绩推断已解决。

## 本地设定工作区 Agent（0.4.0）

顶部新增“本地工作区”，不必创建小说或角色卡。默认单栏讨论；文件和讨论记录按需打开抽屉，查看 / 编辑 / 修改对照时临时展开文档区。讨论、输入草稿和文件夹连接独立保存，小说三栏继续保留。

点击“选择本地文件夹”连接单个系列的资料。模型可以列目录、按字面词搜索、分段读取相关文档，并在回复下显示真实操作记录和引用。仅实际查阅的文档片段会发送到当前模型，不自动上传整个文件夹。支持 UTF-8 / UTF-16 的 MD、TXT、JSON、YAML、TOML、CSV；DOCX 只提取正文、只读，不读取图片或保持排版。PDF、旧 DOC、GBK 和任意 Office 编辑不在首版范围。

默认“仅讨论”。勾选“可提出文档修改”后，Agent 可以生成精确替换 / 新建建议；点击“保存修改”才写入文件。已有文件必须匹配读取时的 SHA-256，保存前备份原始字节、核验备份并再次检查版本；新文件禁止同名覆盖。支持手动编辑、修改对照和历史恢复对照，保留 UTF BOM 与换行。外部编辑冲突会停止覆盖。文件夹切换不改变旧讨论，停止不写入文档，未完成回复与待保存建议可保留。

本地 Agent 需要酒馆的聊天补全连接（DeepSeek、OpenAI 或自定义兼容来源）和支持工具调用的模型；具体服务 / 模型仍需兼容所用工具协议。“参考设置”可选择角色卡与世界书，默认关闭；也可设置本组讨论独立的上下文 / 最大输出，默认 32768 / 4096 tokens，按接口实际支持范围调整。输出包含可能的模型思考，是上限而非承诺长度；不修改角色扮演设置。最多 20 轮工具模型调用 / 32 次工具尝试，预留一次总结；重复读取会显示范围并跳过，达到预算时先整理已知结论。单次读取最多 12000 字符，搜索每次最多 100 份文档、40 个目录，目录展示最多 200 项；结果标明截断。单个文本文件上限 1 MiB / 24 万字符，DOCX 压缩包上限 20 MiB。不提供自动全库长期记忆。

授权来自本机文件夹选择器；页面不能传入绝对路径来授予访问。排除隐藏文件、常见凭据配置、目录链接 / 文件硬链接和软件自身目录。没有命令执行、删除或任意系统文件工具。Agent 消息使用独立 Markdown 渲染及 Shadow DOM，隔离常见聊天渲染与全局选择器；这属于界面封装，不是对同页面第三方脚本的安全沙箱。桌面页面新增受来源校验的窄 IPC 文档接口，Node 集成仍关闭。

工作区连接、讨论、待保存建议与原文备份位于默认数据根的 agent/ 下，按酒馆数据配置分开。桌面更新备份包含这些记录；外部连接文件夹不会因软件更新被整份复制或替换。不要把含私人内容的 agent/、backups/ 或任何测试私有目录上传。首次验证在项目隔离目录和模拟 DeepSeek 服务中进行，不读取真实设定或使用真实账户。

## DeepSeek 回复与停止修复（0.3.3）

小说的上下文预算改用随包可用的本地通用分词器估算，并预留上下文空间，不再等待首次下载 DeepSeek 专用分词器。若本地计数接口也未及时响应，会中断该计数请求并使用保守字节估算。原生世界书激活仍沿用酒馆规则，单独显示读取阶段并设等待上限。

创作对话显示保存、读取参考、整理上下文、等待模型及接收正文等阶段。停止能够中断准备阶段和网络等待，取消后迟到的结果不会恢复旧任务或覆盖新任务；超时及 HTTP 错误会明确显示，保留问题以供重试。

DeepSeek 和自定义 OpenAI 兼容接口遵循原有流式开关，逐步显示正文，推理期间显示状态而不把推理文本当成正文。停止 / 中断后的片段以“未完成草稿”保留，重试不重复用户问题，也不把未完成片段作为已确认回复发送。章节续写 / 润色的中断片段可以通过“未完成草稿”按钮恢复。其他模型来源继续使用原生生成接口，加入任务取消与超时保护。没有修改 API 密钥、上游核心或模型版本。

本地界面验收使用隔离工作区和隐藏 / 离屏 Electron 窗口，窗口不显示、不聚焦，截图保持隐藏；不操作正在使用的浏览器或真实安装。正常启动应用仍按原方式显示窗口。

首次启动只需“开始使用”，软件创建自己的独立工作区；以后默认继续上次使用。工作区是本软件的数据仓库，一部小说在写作区点“新作品”创建，无需为每部小说重新建工作区。连接旧酒馆、复制旧数据、校验恢复等选项统一收进“高级选项”，正常自用无需打开。

## 小说写作与扮演联动（0.3.0）

聊天区上方新增“角色扮演 / 小说写作”切换，保留原聊天输入与消息。写作通过随包内置扩展提供；使用酒馆原生 `menu_button`、`text_pole`、Font Awesome 图标、抽屉和 Popup，颜色、字体及背景跟随酒馆主题。新增 CSS 仅处理布局，不定义另一套主题。

进入写作后创建作品，可管理章节、所属卷、本章大纲与独立写作要求，调整章节顺序，自动保存并手动保存快照。历史保留每章最近 20 次快照；采用候选和恢复历史前也会保存快照。支持导出本章 / 整部作品为 TXT、Markdown，或导出包含历史与来源的 JSON 作品包；作品包导入为新作品，不覆盖已有作品。

“续写”“润色选段”使用当前酒馆连接的模型与生成参数，只将组织后的写作上下文发送给模型，不把当前聊天历史自动混入正文。可选择参考当前角色卡与原生世界书激活结果；世界书各插入位置在写作请求中汇总为参考资料，不保证任意扩展和所有聊天提示词在写作中完全等价。两个模式可以分别记忆已选择的参数预设；未保存到预设的临时参数不作为独立副本保留。写作要求单独存于作品，不改写社区预设。

聊天工具栏和每条非系统消息的更多操作中提供“改写到小说”：选择消息范围、目标章节，模型生成候选，可编辑后追加正文。正文中选中片段，再点“从选段扮演”：使用当前选中的单角色与用户身份创建独立新聊天，把选段来源和场景说明写入该聊天元数据；原聊天与正文保留。此版本不支持从选段直接创建群聊，尚未实现自动时间线和人物知识检查；角色卡与世界书可能包含未来剧情，需由作者排除。试演不会自动修改正式设定。

小说数据保存在当前酒馆用户的 `user/files/desktop-writing-workspace-v1.json`，上一次确认保存的版本在同目录的 `desktop-writing-recovery-v1.json`。同源多窗口使用 Web Locks 串行保存并校验服务器版本；读取失败、格式未知、版本冲突或保存失败时停止覆盖。请保留窗口并导出作品包处理错误。单个作品包目前限制 12 MB；本机数据与完整备份仍含私人正文，请妥善保管。此版本尚无 DOCX / EPUB 导出、安卓端或跨设备同步。

启动时在数据锁内安装 / 更新专属的 `public/scripts/extensions/desktop-writing` 目录，不修改上游核心 JS / CSS。旧扩展代码先校验备份到桌面数据的 `extension-backups`，不会覆盖未识别的同名目录。直接使用现有安装模式也会新增这个专属扩展目录；在普通浏览器打开同一安装也能看到扩展，可通过原生扩展管理禁用。若后端禁用了全部扩展，需要先恢复原生扩展功能。退出、菜单重载、完整备份和更新前会尝试保存写作草稿；失败时取消关闭，以便先导出。

## 安装与使用

运行 `dist/SillyTavern-Desktop-Setup-x64.exe`，安装到当前用户的程序目录或其他可写目录。此个人构建没有代码签名，Windows 可能显示未知发布者。双击桌面或开始菜单的 SillyTavern Desktop；关闭窗口即停止它创建的后端并退出。

正常自用点击“开始使用”即可，开始后通过酒馆顶部的 API 连接配置模型。只有已经在别处安装酒馆且需要继续使用其数据时，才打开高级选项，选择包含 `server.js`、`package.json`、`public`、`src` 的原安装目录。先关闭原来的服务；按实际使用方式选择独立/全局模式及自定义路径。直接模式不迁移数据，不修改网络配置，启动仅覆盖为本机回环、保留 CSRF、禁止自动打开浏览器。上游服务自身启动时可能为原 config.yaml 补齐缺失设置。

高级选项也可创建另一套独立空白工作区，或从旧安装 / 校验备份复制恢复到新副本。首次使用会从安装资源展开后端，耗时取决于磁盘和安全软件。离线可以启动、编辑与查看本地数据，模型推理由用户配置的 API 决定。

再次打开应用会回到上一次成功启动的安装。同一应用第二次启动只激活已有窗口。菜单可重新加载、打开数据目录、停止后端并返回设置、创建校验备份、回到上一次可用配置、打开软件更新和查看许可证。不会后台常驻托盘。

## 软件更新

0.1.0 用户需要手动覆盖安装一次 0.2.0，之后可从启动页“软件更新”或“帮助 → 软件更新”检查我们发布的正式版本。源码仓库与发布页为 [114514547/SillyTavern-Desktop](https://github.com/114514547/SillyTavern-Desktop)。普通代码推送不会触发客户端更新，只有完成测试并发布 Release 才会。

检查 → 阅读改动 → 手动确认下载 → 下载及签名校验 → 保存编辑内容 → 备份并更新。默认不自动下载，不在普通关闭软件时偷偷安装。安装前会停止本应用创建的后端，对所有已保存的独立配置及当前/上一次配置做完整备份；失败则停止更新。更新桌面程序及随包专属写作扩展，不替换已有酒馆核心版本、第三方插件或个人数据。自定义 `--desktop-home` 的用户更新后应使用原启动方式重新打开，以保留该参数。

更新清单使用本项目 Ed25519 发布密钥签名，客户端内置公钥；NSIS 元数据和安装包 SHA-512 都必须匹配签名清单，安装前再次检查。它与 Windows Authenticode 签名不同，本安装器仍为未签名个人构建。更新实现与维护说明见 [UPDATE.md](UPDATE.md)。

## 数据目录

桌面独立数据默认在 `%LOCALAPPDATA%\SillyTavernDesktop`：

| 目录 | 用途 |
| --- | --- |
| `backend/versions/<版本-提交>/<配置ID>` | 可写后端与独立插件 |
| `profiles/<配置ID>/config.yaml` | 独立配置 |
| `profiles/<配置ID>/data` | 所有用户、聊天、角色、密钥等 |
| `backups/<时间-ID>` | 带 SHA-256 清单的完整私密备份 |
| `settings.json` | 当前和上一次成功配置、窗口位置 |
| `shell` | Electron 窗口及浏览器会话数据 |

开发/测试或自定位置可以传入 `--desktop-home="D:\我的酒馆 桌面"`，每个位置仍通过目标数据锁防止并发写入。不要把该目录放在源安装内。

当前上游全局模式的实际数据位于 `%LOCALAPPDATA%\SillyTavern\Data\data`，配置位于其上层 `config.yaml`。如果旧版全局路径不同，请用独立模式明确选择其 configPath 和 dataRoot；不会根据 APPDATA 里是否有文件擅自切换。

## 恢复和故障

启动失败时仍保留中文启动页，可重试、复制诊断状态和打开数据目录。桌面日志只保留固定状态，不收集原始后端输出、聊天正文或 API 密钥。缺依赖、非法 YAML、不可写目录、现有后端和监听归属异常都会停止启动，不会杀掉其他软件的 Node 服务。

若提示目标目录正被使用，先切换到原窗口或关闭原酒馆。对于不完整的 `.sillytavern-desktop.lock`，先确认应用与对应后端均已退出，再保留并移走锁目录；不要对仍运行的服务移锁。正常崩溃由独立守护进程关闭后端，重启时可回收已确认死亡的有效锁。

检测到旧 `public/characters` 时，直接模式会拒绝触发上游的移动迁移。可选择校验备份后创建副本；若同时有新版数据目录则需要先人工整理，避免同名覆盖。符号链接、目录联接、特殊文件、路径越界和备份空间不足都会停止迁移。新副本失败不会切换当前安装，失败中间目录保留用于检查。

备份恢复与注意事项见 [MIGRATION.md](MIGRATION.md)。删除应用不会清除用户数据或旧安装；确需清理时先把完整备份另存，手动处理 `%LOCALAPPDATA%\SillyTavernDesktop`。不要把含私人数据的目录提交到 Git 或发送给别人。

## 从源码复现

构建机需要 Windows x64、Node 24+、Git 和网络；最终安装机器不需要这些工具。

```powershell
npm ci
npm run prepare:vendor
npm run dev
npm run check
npm test
npm run test:integration
npm run test:desktop
npm run test:updates
npm run build:win
# 已打包 EXE 的实际窗口测试
node scripts/smoke-desktop.cjs "dist/win-unpacked/SillyTavern Desktop.exe"
npm run source:zip
```

`prepare:vendor` 固定上游提交、安装锁定的生产依赖、下载并按官方 SHASUMS256 核验 Node、预编译前端、生成逐文件哈希与源码/许可归档。已完成的 bundle 会校验复用。若之前构建中断，请先检查 `build/backend`；将它保留到其他名称后再重新准备，不要清理任何用户数据目录。完整产物是安装器和 `win-unpacked` 多文件目录，后者并非单文件便携 EXE；V1 未额外提供便携 ZIP。

## 已知限制与许可证

详细实测范围见 [TEST_RESULTS.md](TEST_RESULTS.md)。上游固定锁文件在本次 npm 审计中报告 56 项漏洞（4 critical、22 high、29 moderate、1 low），外壳生产依赖为 0 项。保留上游版本，没有擅自执行 `npm audit fix --force`。这不是经过完整安全审计的公开稳定发布；第三方插件和所有上游依赖风险仍需要后续处理。

麦克风、摄像头等网页权限在 V1 禁用；原版文字、图片/文件选择导入照常。自定义插件兼容性、旧版复杂全局安装、干净 Windows 用户和全新系统尚需单独验收。支持签名校验的桌面外壳更新，不自动升级酒馆本体。失败可返回上一配置或从备份创建新副本；桌面二进制回退使用保留的旧安装器。
