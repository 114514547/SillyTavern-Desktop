# 2026-10-25 启动性能审核与修复

后续更新：用户正常启动出现新的 126.6 秒失败记录，已补齐首次缓存无法建立的缺口，并记录隔离 Electron 测试触发的原生弹窗。当前实现、验证和未解决项以[后续报告](2026-10-25-startup-followup.md)为准；本文保留上一轮样本与当时结论。

用户授权在无人值守状态下审核并修复反复启动约一至两分钟的问题。本轮修改桌面源码并使用合成资料验证，没有启动正式 Electron、重启正式后台、改动正式用户资料、调用真实模型、打包或覆盖安装。固定 SillyTavern / Node / Electron 版本保持不变。

已确认并修复重复初始化 Webpack 的开销。同一隔离配置、相同生产计时方式下，后端启动中位数从 **3048 ms 降到 1987 ms，减少 34.8%**。这项收益不能解读为正式实例已经从 114 秒降到两秒：本轮未复现正式实例的分钟级延迟，也没有以正式用户资料运行性能实验。

## 真实记录与根因边界

正式 `startup-latest.json` 的完成时间为北京时间 2026-10-25 01:21:47，总计 113961 ms。旧记录从主进程模块导入之后开始，结束于页面 load，既不包括全部进程启动开销，也不代表所有扩展已经可操作。

| 区间 | 耗时 | 可以确认的含义 |
| --- | ---: | --- |
| 桌面准备到后端派生 | 3184 ms | 扩展准备约 502 ms，非主要瓶颈 |
| 后端派生到 Node 版本输出 | 7245 ms | 进程及入口依赖加载 |
| Node 版本到酒馆版本横幅 | 67633 ms | 配置解析、核心模块导入、用户存储及横幅之前的初始化，旧记录不能再细分 |
| 酒馆横幅到 Webpack 结果输出 | 34769 ms | 数据检查、备份、统计、编译等串行工作，不能全部归为编译 |
| Webpack 结果到后端确认 | 219 ms | 监听、HTTP 与进程归属检查 |
| 后端确认到页面 load | 911 ms | 页面加载 |

正式实例是 managed 配置，核对的四个启动适配目标与固定上游源码完全一致。服务端插件未启用，插件目录为零；只读目录计数也没有显示大量角色或群聊。没有读取聊天正文、小说正文或输出密钥。磁盘剩余空间没有显示磁盘已满。

独立导入实际安装的几个重点依赖并查询版本，合计不足一秒；隔离后端的细分计时也没有复现 67 秒的导入区间。因此，尚不能把特定依赖、杀毒软件、磁盘或 UI 重构认定为分钟级延迟的唯一原因。新计时会在下一次正常源码版启动时进一步区分这些区间。

## 已落实的修复

`startup-runtime.cjs` 通过 Node 的加载钩子为固定版本增加阶段观察和前端缓存适配，不修改磁盘上的上游业务文件。四个目标文件的 SHA-256 必须全部匹配；不支持的版本、被修改的上游文件、不可用的加载钩子会保留原生路径。

managed 配置第一次成功编译后，`frontend-cache.cjs` 记录实际编译输入、上下文目录、缺失依赖和输出的指纹。后续启动重新校验，匹配时直接使用原编译产物，不再初始化 Webpack；任一校验失败则正常编译并重建记录。当前实际编译图包含 1254 个输入文件，合计约 6 MB。存在外部文件依赖、路径越界、链接、编译错误或编译期间修改输入时，不建立可复用记录。

同时启用了 managed 配置私有的 Node 编译缓存。两种缓存都位于 `dataRoot/_cache/desktop-startup/`，沿用原有备份排除规则，不夹带进用户资料备份。existing/global 模式不自动启用这些缓存。设置环境变量 `ST_DESKTOP_DISABLE_STARTUP_CACHE=1` 可以让桌面启动回到原生编译路径，同时保留阶段计时。

主进程现在从 JS 入口开始计时，记录模块导入完成、配置、核心导入、用户存储、各迁移、默认内容、角色缓存、备份、统计、版本查询、编译构造/执行及缓存命中等阶段。后台等待期间每五秒保存一次进度，写入串行化，避免旧进度覆盖新进度。IPC 只转发固定阶段名称及有界数值，不保存原始后台输出、配置或正文。

前端在写作存档与 Agent 均完成初始化后报告 `frontend-interactive`。主进程继续核验当前窗口、主 frame 和准确本机 origin。性能脚本也改为等待这一就绪状态；单独出现 `#dw-modebar` 不再算完整就绪。真实 Electron 中的新 IPC 通知尚未运行验收。

## 验证结果

同一隔离 profile 的公平对照使用生产计时钩子，串行运行，不包含新建 profile 的解包过程，也没有声称操作系统冷启动。

| 模式 | 第一次 | 第二次 | 第三次 | 中位数 |
| --- | ---: | ---: | ---: | ---: |
| 新缓存关闭，原生编译 | 3055 ms | 3048 ms | 3031 ms | 3048 ms |
| 新缓存开启，全部命中 | 2011 ms | 1987 ms | 1964 ms | 1987 ms |

六次启动返回的 `/lib.js` SHA-256 均为 `2d5fb1eedcbefe7062421e8ca54b90a23312f64df8d480c16538714c5157e0bf`。另一次隔离首次编译约 7.7 秒，重启原生编译仍约 0.9 秒；这些数值用于解释重复工作，不外推为正式实例的 34.77 秒全是编译。

98 个 JavaScript 文件语法检查、118 项单元测试通过。真实原生后端集成通过，覆盖 CSRF 拒绝、角色卡/世界书导入、预设保存、仅本机模拟模型请求、聊天保存及重启持久化、缓存命中不调用编译器，以及产物损坏、输入变化、记录损坏和未知上游文件四种原生回退。备份恢复到新配置后资料仍可读，缓存不进入资料备份。

完整原生前端首次运行及缓存命中后的 27 项 headless Edge 检查均通过，页面错误为零。最终缓存命中样本的后端就绪耗时 1926 ms，页面导航到写作与 Agent 初始化完成耗时 2235 ms；这是分阶段的 headless 测量，不是完整 Electron 启动总时长。检查包含设置读写、世界书条目、原生 DOM 归属、三模式布局、键盘、主题及删除保护，最终结果见本机 `ui/after-report.json`。

测试过程遇到两类夹具问题并处理：并行测试争抢默认测试端口，现改用随机端口并串行验收；重复 UI 测试固定使用同名世界书，现改用唯一名称并明确等待原生编辑器加载和抽屉内容创建。没有通过放宽生产监听归属校验或跳过业务检查来获得通过。

## 生效与剩余工作

正常退出当前酒馆后，通过原有源码开发版入口重新启动即可加载本轮改动，不需要重装。第一次会建立缓存，后续复用；刷新页面不能替代主进程重启和内置扩展同步。没有修改现有正式实例或旧安装包。

收尾复查的最新正式启动记录仍是上述 schema 1 的 114 秒样本。尚待正式实例下一次自然启动的细分记录，才能判定那次延迟的具体函数及本轮改动在正式环境中的收益。未验证操作系统冷启动、正式 Electron IPC、所有第三方扩展和新安装包。没有关闭系统防护、移动数据、升级依赖或宣称分钟级问题已经完全消失。
